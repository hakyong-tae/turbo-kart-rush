# 진행 시스템: 서버 구조 설계

2026-11-18. `2026-11-17-update-decisions.md` 4절(버는 쪽·쓰는 쪽·화면, 승인됨)의 서버 쪽 설계다.
숫자와 화면은 그 문서가 기준이고, 이 문서는 "어디에 저장하고, 누가 계산하고, 무엇을 믿지 않는가"를
정한다. 결정 문서와 다르게 간 곳은 마지막 절에 이유와 함께 모았다.

## 1. 원칙

1. **계산은 전부 `server.js`.** 클라이언트는 레이스에서 일어난 사실(순위, 난이도, 카운터)을 보내고,
   코인·경험치·미션 진행·레벨·출석 보상은 서버가 자기 표로 계산한다. 클라이언트가 보낸 코인 숫자는
   어디에도 없다.
2. **상태는 유저 스테이트 하나.** 새 컬렉션을 만들지 않는다(컬렉션은 `{ limit }` 조회만 되고 전체를
   읽어야 해서 계정별 지갑에 맞지 않는다).
3. **규칙 표는 두 곳.** `server.js`(계산)와 `src/core/economy.ts`(가격표·레벨 바·미션 문구 표시).
   `src/verse8/serverEconomy.test.ts`가 서버 소스에서 표를 꺼내 클라이언트 값과 비교한다
   (`serverLists.test.ts`와 같은 방식).
4. **로컬 모의 = 같은 `server.js`.** Verse8 호스트 밖에서는 `server.js`를 그대로 브라우저에서 실행하고
   `$global`만 `localStorage`로 바꾼다(`src/verse8/localServer.ts`). 규칙을 두 번 구현하지 않으므로
   로컬과 서버가 어긋날 수 없다. 호스트 안에서는 이 코드가 로드되지 않는다(동적 import).

## 2. 유저 스테이트

기존 키(`premium`, `premiumRaces`, `nickname`, `cos`, `grants`, `cups`, `daily`)는 그대로 둔다.

| 키 | 형식 | 내용 |
|---|---|---|
| `coins` | 정수 ≥ 0 | 코인 잔액 |
| `xp` | 정수 ≥ 0 | 누적 경험치. 레벨은 저장하지 않고 여기서 계산한다 |
| `own` | 문자열 | 항목별 소유 목록. 아래 "소유 토큰" |
| `eco` | `{ day, races, doubles, swaps }` | UTC 하루치 장부: 보상 받은 판 수, 2배 광고 횟수, 미션 교체 횟수 |
| `race` | `{ id, at, trackId, characterId, difficulty, mode }` | 시작했지만 아직 정산 안 된 레이스 1건 |
| `award` | `{ id, coins, doubled }` | 마지막 정산의 레이스 코인(2배 광고 대상) |
| `mis` | `{ day, ids[3], p[3], done[3], bonus }` | 오늘의 미션 3개와 진행도 |
| `streak` | `{ last, n, total }` | 마지막 출석일, 연속 일수, 누적 출석 일수 |

### 소유 토큰

`own`은 쉼표로 이은 토큰 문자열이다. 외형 토큰은 `cos` 묶음 문자열의 토큰과 **같은 표기**
(`<종류 한 글자>:<카탈로그 인덱스 36진수>`, 예: `p:f` = 라이버리 15번)이고, 카트는 `k:<캐릭터 id>`다.

```
own = "g:3,p:1,t:a,k:fennec"
```

- `cos`와 같은 문자셋(`[a-z0-9:,]`)이라 같은 정규식으로 걸러진다. 최대 94개(외형 87 + 카트 7) ≈ 400자.
- 카탈로그 배열은 뒤에만 추가하므로 인덱스가 곧 영구 id다(`cos`가 이미 같은 규칙에 기대고 있다).
- **파생 소유**: 레벨 보상과 출석 보상은 `own`에 쓰지 않고 `xp`·`streak.total`에서 매번 계산해
  합친다(`_ownSet` = 저장된 `_boughtSet` + 파생). 지급 누락이 생길 수 없고, 나중에 보상 항목을
  바꿔도 기존 계정이 자동으로 따라온다. `getMyEntitlements().own`은 합친 결과를 준다.

### 소유 판정 (한 곳)

```
열림(token) = 무료 항목
           || own에 있음 (코인 구매 + 파생 소유)
           || (premium && 획득 전용이 아님)
```

- 서버: `_owns(state, token)`. `setCosmetics`가 이제 이 판정으로 **안 가진 유료 토큰을 걸러서** 저장한다
  (지금까지는 불투명 저장이라, 손댄 클라이언트가 유료 외형을 기록판에 올릴 수 있었다).
- 클라이언트: `sanitize(cos, premium, owned?)`에 세 번째 선택 인자(소유 토큰 집합)를 추가한다.
  `owned`를 넘기면 위 판정 그대로, 넘기지 않으면 기존 동작(`premium`이면 전부 통과)이다. 남의 카트를
  그리는 곳(`sanitize(x, true)`)은 손대지 않는다: 획득 전용 외형도 남의 화면에서는 보여야 한다.

## 3. 기존 `premium`(100VX) 보유자와의 관계

- `premium`은 지금처럼 **기존 유료 외형 73종 + 프리미엄 카트 7종**을 즉시 연다. 저장 형식도 그대로
  (`premium: true`)라 기존 구매자는 마이그레이션이 없다.
- `premium` 보유자가 73종 중 하나를 `buyCosmetic`으로 사려 하면 서버는 코인을 깎지 않고 `owned`로 답한다.
- 획득 전용 14종은 `premium`으로 열리지 않는다. 코인 진열대 5종은 `premium` 보유자도 코인으로 산다.
- 코인으로 산 뒤 100VX를 결제해도 환불은 없다(`own`은 그대로 남고, 판정만 `premium`이 먼저 통과시킨다).
- 프리미엄 카트: `k:<id>`를 가졌으면 `consumePremiumRace`가 이용권을 쓰지 않는다. 광고 3회권은 유지.

## 5. 레이스 정산: 무엇을 믿지 않는가

레이스 시뮬레이션은 브라우저에서 돈다(오프라인 AI전은 전부, 온라인은 방장 브라우저). 서버는 순위를
**검증할 수 없다.** 그래서 순위를 믿되, 한 계정이 하루에 뽑아낼 수 있는 양에 천장을 둔다.

1. **시작-종료 짝.** `beginRace`가 서버 시각을 찍고 `raceId`를 준다. `finishRace`는 그 id와 맞아야
   하고, 정산하면 `race`를 지운다(한 번 시작 = 한 번 정산). 서킷·카트·난이도·모드는 종료 보고가 아니라
   **시작 때 서버에 저장된 값**을 쓴다.
2. **지급 간격 = 실제 시간.** 보고한 레이스 시간 `timeMs`는 30초 이상이어야 하고, 서버가 잰 경과 시간이
   `timeMs × 0.95` 이상이어야 한다. 즉 보상 한 번에 실제 시간 30초 이상이 든다. 빨리감기·즉시 완주
   호출은 거절된다(`too-fast`).
3. **하루 감쇠와 천장.** UTC 하루에 10판까지 전액, 11판부터 30%, **61판부터 0**(이 문서에서 추가, 6절).
4. **카운터는 깎아서 받는다.** 미션용 카운터(드리프트 부스트, 아이템 사용 등)는 정수로 바꾸고 판당
   상한으로 자른다. 미션 보상은 하루 3개 + 보너스로 이미 상한이 있다.
5. **광고는 호스트가 검증한 뒤에만 호출**(`grantPremiumRaces`와 같은 신뢰 모델)하되, 서버가 하루 횟수를
   센다: 2배 5회, 미션 교체 1회, 출석 복구는 "딱 하루 빠졌을 때"라는 조건이 서버 날짜로 판정된다.
7. **시작 호출이 유실돼도 판을 잃지 않게.** `beginRace`가 실패하면 클라이언트가 레이스 중 3·6·12·24초
   간격으로 다시 부른다. 늦게 성공하면 정산 때 `timeMs`를 "서버가 확인해 준 뒤 지난 시간"으로 줄여
   보낸다(서버가 본 만큼만 청구). 그 시간이 30초에 못 미치면 `bad-time`으로 거절되고, 끝내 시작이
   기록되지 않았으면 클라이언트가 `no-race`로 처리한다. 어느 경우든 결과 화면에 이유가 적힌다
   (서버 무응답 / 시작 미기록 / 서버 거절 + 사유 코드). 조용한 0코인은 없다.
6. **개발용 주행은 정산하지 않는다.** `?auto`·`?b.<path>=` 오버라이드 레이스는 기록 제출과 마찬가지로
   클라이언트가 정산을 요청하지 않는다.

최악의 경우(스크립트가 30초마다 1등·어려움으로 보고): 10×78 + 50×23 = 1,930코인/일. 정상 유저 약
450코인의 4배 남짓이고, 코인은 현금·VX로 바뀌지 않으며 얻는 것은 자기 계정의 외형뿐이다.

### 정산 식

```
레이스 코인 = round(순위표[place] × 난이도% × 감쇠% / 10000)     ※ 정수 연산(부동소수 차이 방지)
레이스 경험치 = round(경험치표[place] × 감쇠% / 100)
난이도% = 쉬움 80 / 보통 100 / 어려움 130      감쇠% = 100(1~10판) / 30(11~60판) / 0(61판~)
```

리타이어는 순위와 무관하게 리타이어 칸(코인 5, 경험치 10)을 쓴다. 팀전도 개인 순위로 계산한다.
온라인 레이스도 같은 표로 정산한다(방 설정 난이도).

`finishRace`의 답: `{ ok, reason?, coins(잔액), earned: { race, missions, levels, total }, races(오늘
판 수), rate(이번 판 감쇠%), xp, xpEarned, level, levelUps, missions, unlocked[], raceId }`.

## 6. 미션·출석·레벨 (2단계)

### 미션

- 후보 표는 서버에 있다: `{ id, tier, target, stat? }`. `stat`이 있으면 "보고된 카운터를 더하는"
  미션, 없으면 "조건을 채운 레이스 1회 = +1"인 미션이다.
- 그날의 3개(쉬움·보통·어려움 하나씩)는 **서버가** 날짜 시드(`seedOf(day)`, `core/daily.ts`와 같은
  FNV-1a)로 고른다. 전원 동일. 클라이언트는 서버가 준 목록(`ids`, 지정 서킷·체급 같은 매개변수 포함)을
  그리기만 한다. 고르는 로직이 한 곳이라 어긋날 수 없다.
- 지정 서킷·체급은 미션 id에 붙여 보낸다: `track:coral_coast`, `class:heavy`.
- 날짜가 바뀌면 `mis`를 새로 만든다(읽을 때 판정, 별도 작업 없음).
- 완료 판정은 `finishRace` 안에서. 완료 즉시 자동 지급, 3개째에 보너스 100.
- 교체: 같은 등급에서 지금 3개에 없는 다음 후보로. 진행도 0에서 다시.
- 레이스 중 알림: 카운터 미션은 클라이언트가 `진행도 + 이번 레이스 카운터 ≥ 목표`를 직접 볼 수 있어
  그 순간 토스트를 띄운다. 표시용이고, 지급은 정산 때 서버가 한다.
- 카운터는 `src/game/RaceStatsTracker.ts`가 이벤트 버스에서 센다: `drift`(2단계 이상
  `kart:driftEnd`), `draft`(`kart:draftEnd` burst), `start`(`kart:boost` source `start`),
  `items`(`item:use`), `hits`(내가 쏜 `item:hit`), `tricks`(`kart:trick` landed), `walls`(벽·장애물
  `kart:collision`). 서버 상한은 `STAT_CAP`.
- 정산 시점: 플레이어가 결승선을 지난 순간(결과 화면을 기다리지 않고 나가도 받는다). 단 팀 점수전은
  전원의 순위가 정해져야 승패가 나오므로 결과 화면 진입 때 정산하고, 그 전에 나가면 승리 없이 정산한다.

### 획득 전용 외형 14종

기존 종류의 카탈로그 뒤에 붙였다(`earn: true`). 100 VX로는 열리지 않는다.

| 얻는 법 | 항목 (토큰) |
|---|---|
| 레벨 5 / 10 / 15 / 20 / 25 / 30 | 엠블럼 메달 `g:9` / 휠 골드 림 `w:5` / 트레일 혜성 `t:b` / 화염 오로라 `f:9` / 트레일 색종이 `t:c` / 엠블럼 월계관 `g:a` |
| 누적 출석 7 / 14 / 30일 | 엠블럼 태양 `g:b` / 화염 새벽빛 `f:a` / 트레일 눈송이 `t:d` |
| 코인 진열대 | 휠 네온 림 `w:6` 1,500 / 엠블럼 트로피 `g:c` 1,500 / 화염 인페르노 `f:b` 2,000 / 트레일 유성 `t:e` 2,000 / 화염 초신성 `f:c` 2,500 |

가격표에서 -1은 "팔지 않음"(레벨·출석 보상)이다. `buyCosmetic`은 이런 토큰에 `earn`으로 답한다.

### 출석

- `claimAttendance()`를 그날 처음 부르면 지급. `last`가 어제면 `n+1`, 오늘이면 변화 없음,
  그제면(딱 하루 빠짐) `recover` 없이 부르면 **아무것도 하지 않고** `canRecover: true`로 답해
  클라이언트가 "광고 보고 이어가기 / 1일차부터"를 묻게 한다. `recover: true`는 이어가고,
  `recover: false`를 명시하면 1일차로 돌아간다. 그보다 오래 빠졌으면 1일차.
- 보상 코인은 `[50, 60, 80, 100, 120, 150, 300][(n-1) % 7]`.
- 누적 7·14·30일 보상은 `streak.total` 기준(연속이 끊겨도 누적은 남는다). 파생 소유.

### 레벨

- `level(xp)`: 다음 레벨까지 100, 150, 200, … (레벨마다 +50), 최고 30(누적 23,200).
- 레벨업 1회당 코인 100. 5·10·15·20·25·30레벨 보상은 파생 소유.

## 7. 클라이언트 구조

| 파일 | 역할 |
|---|---|
| `src/core/economy.ts` (신규) | 순위표·난이도·가격표·레벨 곡선·출석표·미션 표의 클라이언트 사본과 순수 함수. 표시용 |
| `src/core/cosmetics.ts` | `sanitize`에 `owned` 선택 인자, 토큰 헬퍼, 획득 전용 표시(`earn`) 추가. 기존 값 불변 |
| `src/verse8/localServer.ts` (신규) | 호스트 밖에서 `server.js`를 `localStorage` 유저 스테이트로 실행 |
| `src/verse8/backend.ts` (신규) | 호스트 안이면 게임서버, 밖이면 로컬 서버로 가는 호출 한 곳 |
| `src/verse8/entitlements.ts` | 캐시에 `coins`·`own`·… 추가, 구매·정산 래퍼. 로컬 모의는 로컬 서버 경유로 교체 |
| `src/ui/*` | 로비 프로필 바, 결과 보상 줄, 차고 가격표·구매 시트, 잠금 시트 코인 버튼, 출석 창, 미션 패널 |
| `src/game/RaceStatsTracker.ts` (신규) | 레이스 한 판 동안 미션 카운터를 이벤트 버스에서 센다 |

화면 배치에서 결정 문서와 달라진 점: "미션" 버튼과 "출석" 버튼을 로비 버튼 묶음 맨 앞 줄에 두었다
(프로필 바는 레벨·경험치 바·코인·연속 일수 표시 전용). 키보드·패드 이동이 기존 2열 규칙 그대로 된다.
출석 창은 그날 처음 로비에 들어왔을 때 한 번 저절로 열리고(`?auto` 주행 제외), 이후에는 버튼으로 연다.

서버가 답하지 않을 때: 정산·구매는 실패로 끝나고 잔액은 바뀌지 않는다(낙관적 반영 없음). 코인은
"받았다고 보였는데 사실은 아닌" 것이 가장 나쁜 실패라, 차고 도색 저장과 달리 서버 답을 기다린다.

## 8. 결정 문서와 다르게 간 곳

| 항목 | 결정 문서 | 여기서는 | 이유 |
|---|---|---|---|
| 프리미엄 카트 수 | 3종 | 7종(`fennec`·`bram`·`rosa`·`coco`·`zorp`·`vera`·`brine`) 각 2,500 | 11-18 카트 확장으로 늘었다. 합계가 17,500코인이 된다 |
| 하루 천장 | 10판 뒤 30% | + 61판부터 0 | 서버가 순위를 검증할 수 없어서 상한이 필요하다. 60판은 약 2시간 반 분량 |
| 감쇠 대상 | 코인(명시 없음) | 코인과 경험치 모두 | 경험치만 전액이면 레벨업 코인(100)으로 감쇠를 우회한다 |
| 미션 후보 | 14종 | 16종 | 문서의 목록이 실제로 15개였고, "점프 묘기 5회"를 문서 예고대로 추가 |
| `setCosmetics` | 불투명 저장 | 소유 판정으로 거름 | 항목별 소유가 생기면 서버가 유일한 판정자여야 한다 |
| 출석 보상 기준 | "누적 7·14·30일" | `streak.total`(끊겨도 유지) | "누적"을 글자 그대로 읽었다. 연속 기준이면 30일 보상이 사실상 닿지 않는다 |
| 획득 전용 외형 | 일부를 헬멧 장식으로 | 기존 종류(엠블럼·트레일·화염·언더글로우·휠)에 추가 | 헬멧 장식은 새 외형 종류라 `src/kart` 모델 작업이 따로 필요하다. 후속으로 남긴다 |
| 광고 placement | (미정) | `rewarded_double_coins`·`rewarded_streak_recover`·`rewarded_mission_swap` 추가 | 곳마다 지표를 따로 보기 위해. 콘솔 등록 필요 |
